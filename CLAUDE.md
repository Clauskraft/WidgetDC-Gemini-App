## Stack

- **TanStack Start** (React 19 SSR + file-based routing) on **Vite 7** + **Tailwind v4**.
- Config comes from `@lovable.dev/vite-tanstack-config` — it already wires
  `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, `nitro`, the
  `@` path alias, and `VITE_*` env injection. **Do NOT re-add these plugins** in
  `vite.config.ts` or the app breaks with duplicate plugins.
- Build target defaults to **Cloudflare** via nitro (see backlog AUR-7 for the
  Railway-vs-Cloudflare deploy decision — the old Railway/Nixpacks config was
  removed).
- Node `>=22`. The source was developed with **bun** (`bun.lock`), but `npm`
  works; we pin `nitro@3.0.260603-beta` to satisfy the Lovable config peer dep.

## Commands

- `npm run dev` — Vite dev server (SSR + HMR), single process.
- `npm run build` — Vite client build + nitro SSR server bundle into `dist/`.
- `npm run preview` — Preview the production build.
- `npm run lint` — ESLint (flat config, `eslint.config.js`).
- `npm test` — **Vitest** unit/component suite (97 tests across 9 files).
- `npm run test:e2e` — **Playwright** (graph + model-picker visual specs;
  needs `npm run test:e2e:install` once for the chromium binary).
- `npm run docs:bridge-errors[:check]` — regenerate/verify the MCP-bridge error
  payload docs from `src/lib/widgetdcContracts.ts` (keep docs in sync).

## Architecture

### Server entry & middleware
- `src/server.ts` — SSR `fetch` wrapper. Normalizes h3-swallowed 500s and
  renders a styled error page; defers to `@tanstack/react-start/server-entry`.
- `src/start.ts` — `createStart` with an error `requestMiddleware` and the
  Supabase auth `functionMiddleware` (`attachSupabaseAuth`).
- `src/router.tsx` / `src/routeTree.gen.ts` — router + generated route tree
  (regenerated by the router plugin; don't hand-edit the `.gen.ts`).

### Routes (`src/routes/`, file-based)
- `index.tsx`, `c.$threadId.tsx` — chat shell + per-thread conversation.
- `dashboard.tsx` — mission-control overview (threads, gems, model).
- `gems.tsx` / `gems.$gemId.tsx` — "Gems" (saved system-prompt personas).
- `visual.graph.tsx` — **Playwright-only** deterministic graph render harness
  (not in app nav).
- `embed.canvas.$canvasId.tsx` — signed-token canvas embed (the postMessage
  bridge consumer; see contracts below).
- `settings.tsx`, `debug.logs.tsx`.
- `api/chat.ts` — chat proxy. **Currently streams via the Lovable AI Gateway**
  (`LOVABLE_API_KEY`). Backlog AUR-1 routes this through the WidgetDC
  orchestrator for model-policy / budget / RAG.
- `api/mrp.canvas.resolve.ts` — `POST /api/mrp/canvas/resolve`: resolves a brief
  to a visualization family + signed embed URL (canvas_builder bridge, CFDS §9).

### WidgetDC integration surface (already present)
- `src/lib/widgetdcContracts.ts` — `@widgetdc/contracts` mirror: Zod schemas for
  `ResolveCanvasRequest/Response`, the `widgetdc.bridge.v1` postMessage envelope,
  origin allow-list + rejection helpers, and `CanvasTokenPayload`. **Client-safe.**
- `src/lib/widgetdcContracts.server.ts` — HMAC-SHA256 token signing/verifying
  (`.server.ts` keeps `node:crypto` out of the bundle).
- `src/lib/visualizationIntent.ts` — 10 visualization standards + `detectIntent`
  (keyword + node-type scoring) feeding the canvas resolver.
- `src/components/FlowFigure.tsx` — CFDS canvas renderer: 17 canonical node
  types + legacy aliases, eigenvector layout, provenance/confidence/regulatory
  overlays, swimlanes. `MermaidBlock`/`GraphBlock`/`KnowledgeGraphBlock` render
  fenced figure blocks (`src/lib/figureBlocks.ts`).
- `src/lib/mermaidToDrawio.ts` — mermaid → draw.io mxGraph export (CFDS §10).

### Persistence & auth
- `src/integrations/supabase/*` — Supabase client (browser + `client.server.ts`),
  `auth-attacher` / `auth-middleware`. Thread storage in `src/lib/threadStorage.ts`
  + `src/hooks/useThreads.ts`.

## Conventions & invariants

- **Secrets are server-only.** Keys live in `.env` (gitignored) and are read via
  `process.env` **inside handlers/functions**, never at module scope (Cloudflare
  binds env per-request). `*.server.ts` suffix and `process.env` keep secrets out
  of the client bundle. `VITE_*` values are PUBLIC — only the Supabase anon key
  belongs there.
- **Validate request bodies with Zod** on every server handler (see
  `api/mrp.canvas.resolve.ts` for the pattern).
- **Governance is UI-side display only** — real write-enforcement must stay
  server-side / on the WidgetDC platform. Client-supplied governance context is
  for operator clarity, never trusted as authority. See `docs/widgetdc-aurora/`
  for the integration + browser-safety checklist.
- **Canvas bridge safety:** all `widgetdc.bridge.v1` messages are origin-checked
  + schema-validated (`validateIncomingBridgeMessage`); embed tokens are HMAC
  signed and TTL-bounded. Keep `docs/mcp-bridge-*.md` regenerated via
  `npm run docs:bridge-errors`.
- **Claim-safe wording** — no "production-ready"/"proven" claims without runtime
  evidence.
